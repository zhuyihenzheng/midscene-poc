# ポイントクーポン交換サイト 設計書（デモ）

会員が保有ポイントでクーポンを交換する Web サイト。自動テスト（Midscene / Playwright 切替）の新規サイト適用を試すためのデモ。

- 起動：`node sites/coupon-demo/app/server.mjs`（既定 http://localhost:8090/）
- 試験用会員：会員ID `M0001`／パスワード `pass1234`（初期保有ポイント 1,200 pt）
- データはメモリ上のみ。起動時・`POST /__test/reset` で初期データに戻る

## 画面一覧

| ID | 画面名（見出し） | URL |
|---|---|---|
| S01 | ログイン | `/login` |
| S02 | マイページ | `/` |
| S03 | クーポン一覧 | `/coupons` |
| S04 | クーポン交換 | `/coupons/{id}/exchange` |
| S05 | 交換内容の確認 | `POST /coupons/{id}/confirm` の応答 |
| S06 | 交換完了 | `/exchanges/{交換番号}` |
| S07 | 交換履歴 | `/history` |

未ログインで S02〜S07 にアクセスした場合は S01 へ遷移する。

## S01 ログイン

- 入力項目：会員ID（必須）、パスワード（必須）
- 未入力：各項目の下に「会員IDを入力してください。」「パスワードを入力してください。」
- 認証失敗：画面上部に「会員IDまたはパスワードが正しくありません。」。入力した会員IDは保持し、パスワードは空にする
- 成功：S02 へ遷移

## S02 マイページ

- 会員名と保有ポイント（3 桁区切り＋「pt」、例「1,200 pt」）を表示
- 「クーポン一覧」「交換履歴」へのリンク、〈ログアウト〉ボタン（S01 へ）

## S03 クーポン一覧

- 列：クーポン名／カテゴリ／必要ポイント（例「300 pt」）／在庫（例「10 枚」）／操作
- 在庫がある行は操作列に「交換する」リンク。在庫 0 の行は「在庫なし」と表示し、リンクは出さない
- カテゴリで絞り込み：ラジオボタン「すべて／飲食／買物／娯楽」（初期値：すべて）＋〈絞り込む〉
- 画面上部に現在の保有ポイントを表示

初期データ：

| ID | クーポン名 | カテゴリ | 必要ポイント | 在庫 |
|---|---|---|---|---|
| 1 | カフェ 200円引き | 飲食 | 300 | 10 |
| 2 | ベーカリー 100円引き | 飲食 | 150 | 0 |
| 3 | 書店 500円券 | 買物 | 600 | 2 |
| 4 | 映画 1,000円券 | 娯楽 | 1,200 | 3 |

## S04 クーポン交換

- 表示：クーポン名、必要ポイント（1 枚あたり）、在庫、保有ポイント
- 入力項目
  - 枚数（必須）：半角数字、1〜5
  - 受取方法（必須）：ラジオボタン「メール／アプリ」（初期値なし）
  - メールアドレス：受取方法＝メールのときだけ表示・必須。アプリに切り替えて非表示になったときは入力値をクリアする
- 〈確認〉で入力チェック。エラーは各項目の下に表示し、入力値は保持する

| 条件 | メッセージ |
|---|---|
| 枚数が未入力 | 枚数を入力してください。 |
| 枚数が半角数字以外 | 枚数は半角数字で入力してください。 |
| 枚数が 1〜5 の範囲外 | 枚数は1〜5の範囲で入力してください。 |
| 受取方法が未選択 | 受取方法を選択してください。 |
| メール選択時にメールアドレスが未入力 | メールアドレスを入力してください。 |
| メールアドレスの形式誤り | メールアドレスの形式が正しくありません。 |

- 項目チェックが通ったあと、次の順で業務チェックし、エラーは画面上部に表示する
  1. 在庫：枚数 ＞ 在庫 →「在庫が不足しています（残り N 枚）。」
  2. ポイント：必要ポイント合計（必要ポイント × 枚数）＞ 保有ポイント →「保有ポイントが不足しています。」
  - **保有ポイントと必要ポイント合計が同じ場合は交換できる**（交換後の保有ポイントは 0 pt）
- 「クーポン一覧へ戻る」リンク

## S05 交換内容の確認

- 表示：クーポン名、枚数（例「2 枚」）、受取方法、メールアドレス（メールのときのみ）、必要ポイント合計、交換後の保有ポイント
- 〈交換する〉：交換を確定し S06 へ。〈戻る〉：S04 へ戻り、入力値（枚数・受取方法・メールアドレス）を保持

## S06 交換完了

- 「クーポンの交換が完了しました。」、交換番号（EX-000001 形式の連番）、交換後の保有ポイントを表示
- 交換確定時、ポイント基盤 API へポイント使用を 1 回送信する
  - 電文：`{ "API": "POINT_USE", "KAIIN_NO": 会員ID, "USE_PT": 必要ポイント合計, "COUPON_ID": クーポンID, "MAISU": 枚数, "KOKAN_NO": 交換番号 }`
  - デモでは送信内容を `GET /__test/ledger` で確認できる（WireMock の受信履歴に相当）
- 在庫は枚数分減り、保有ポイントは合計分減る

## S07 交換履歴

- 新しい順に一覧：交換番号／クーポン名／枚数／使用ポイント／受取方法
- 履歴がない場合は「交換履歴はありません。」
