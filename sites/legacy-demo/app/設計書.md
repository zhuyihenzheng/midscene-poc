# 受注管理システム 設計書（レガシー画面のデモ）

受注の検索・登録・取消を行う社内向け Web システム。label や h1 を持たない古い作りの画面に、自動テストを適用できることを確かめるためのデモ。

- 起動：`node sites/legacy-demo/app/server.mjs`（既定 http://localhost:8095/）
- 試験用ユーザー：ユーザーID `u001`／パスワード `pass1234`
- データはメモリ上のみ。起動時・`POST /__test/reset` で初期データに戻る

## 画面一覧

| ID | 画面名 | URL |
|---|---|---|
| G00 | ログイン | `/login` |
| G01 | 受注検索 | `/orders` |
| G02 | 受注登録 | `/orders/new` |
| G03 | 受注詳細 | `/orders/{受注番号}` |

画面名は画面上部の帯に表示する。未ログインで G01〜G03 にアクセスした場合は G00 へ遷移する。

## G00 ログイン

- 入力項目：ユーザーID、パスワード
- 認証失敗：画面上部に「ユーザーIDまたはパスワードが違います。」。入力したユーザーIDは保持する
- 成功：G01 へ遷移

## G01 受注検索

- 検索条件：顧客名（部分一致）、ステータス（すべて／受付／出荷済／取消。初期値：すべて）、至急（チェックすると至急の受注のみ）
- 初期表示：条件なしで検索した結果（全 5 件）を表示する
- 〈検索〉：結果を取得する間は「検索中…」を表示し、取得後に件数（例「5 件」）と一覧を表示する
- 一覧の列：受注番号／顧客名／商品／数量／金額／ステータス／至急。受注番号の順に並べる
  - 金額は単価 × 数量。3 桁区切り＋「円」（例「240,000 円」）
  - 至急の受注は至急列に「至急」、それ以外は空欄
  - 受注番号は G03 へのリンク
- 該当なし：件数「0 件」と「該当する受注はありません。」を表示し、一覧は表示しない
- 〈新規登録〉：G02 へ

## G02 受注登録

- 入力項目
  - 顧客名（必須）：20 文字以内
  - 商品（必須）：商品マスタから選択（初期値「選択してください」）
  - 数量（必須）：半角数字、1〜99
  - 至急：チェックボックス（初期値：オフ）
  - 備考：任意
- 〈登録〉で入力チェックを行う。エラーは上の項目から順に調べ、最初の 1 件をダイアログで表示する。入力値は保持する

| 条件 | メッセージ |
|---|---|
| 顧客名が未入力 | 顧客名を入力してください。 |
| 顧客名が 20 文字を超える | 顧客名は20文字以内で入力してください。 |
| 商品が未選択 | 商品を選択してください。 |
| 数量が未入力 | 数量を入力してください。 |
| 数量が半角数字以外 | 数量は半角数字で入力してください。 |
| 数量が 1〜99 の範囲外 | 数量は1〜99の範囲で入力してください。 |

- 入力チェックが通ると確認ダイアログ「登録します。よろしいですか？」を表示する
  - OK：受注を登録し、G03 へ遷移して「受注を登録しました。」を表示する。受注番号は連番（初期データの次は J-0006）、ステータスは「受付」
  - キャンセル：登録せず、G02 のまま入力値を保持する
- 登録時、在庫引当 API へ引当を 1 回送信する
  - 電文：`{ "API": "HIKIATE", "JUCHU_NO": 受注番号, "SHOHIN_CD": 商品コード, "SURYO": 数量 }`
  - デモでは送信内容を `GET /__test/requests` で確認できる
- 〈一覧へ戻る〉：G01 へ

## G03 受注詳細

- 表示項目：受注番号、顧客名、商品、数量、単価、金額、ステータス、至急（「至急」／「通常」）、備考
  - 単価・金額は 3 桁区切り＋「円」（例：単価「120,000 円」、金額「240,000 円」）
- 〈取消〉：ステータスが「受付」の受注にだけ表示する。確認ダイアログ「この受注を取り消します。よろしいですか？」を表示する
  - OK：ステータスを「取消」にし、「受注を取り消しました。」を表示する。〈取消〉は表示しなくなる。在庫引当 API へ引当解除を 1 回送信する
    - 電文：`{ "API": "HIKIATE_KAIJO", "JUCHU_NO": 受注番号 }`
  - キャンセル：ステータスは変えず、電文も送信しない
- 〈一覧へ戻る〉：G01 へ
